# 策略无 A/B · 说不清打标到底有没有用

## 背景

- 当前链路已具备“数据准入与人工打标”“标签粒度与证据边界”“人群分层及动作建议”的规划，但策略发布后缺少受控对照：无法区分结果变化来自标签、分层规则、触达内容、执行人员、时间窗口或案件构成变化。
- 在没有基线、随机分流、暴露记录和统一结果口径的情况下，运营只能观察总量指标；即使某标签覆盖的案件转化更高，也不能证明“使用该标签”带来了增益，可能只是该人群本身价值更高或被优先处理。
- 将标签直接全量接入策略存在风险：无效标签会消耗触达和人工产能，错误标签会造成不当触达或遗漏；同时若实验绕过数据时效、标签审核、同意状态、频控或既有策略保护，也会破坏上游约束。
- 本任务建立标签和策略的 A/B 评估闭环，使运营能够在限定人群和风险边界内回答：某个已发布标签（或依赖该标签的策略变体）是否带来可定义、可复现且足以支持推广的业务增量。

## 目标

- 支持针对“标签是否参与策略决策”或“不同标签驱动策略”的受控实验，形成实验定义、资格筛选、稳定分流、策略暴露、结果回流、统计判定和发布决策的完整闭环。
- 让每个实验结果可解释：可查看使用了哪些标签及版本、对照策略与实验策略的唯一差异、受试样本构成、实际执行情况、结果归因窗口和排除原因。
- 保护用户权益、数据质量与运营安全：未审核、过期、待同步、撤销或不适用于当前业务线的标签不得进入实验策略；合规阻断、退订/拒绝、冷却期、频控及高风险人工复核优先于任何实验分组。
- 输出可用于推广、调整、暂停或否决策略的结论，而非只展示点击量或原始转化率；支持将被验证有效的策略版本按审批流程灰度推广。

## 范围

### 纳入范围

- 面向单一业务目标、目标人群、基线策略和标签策略变体的 A/B 实验配置、审批、预检、启动、暂停、结束和归档。
- 受试案件资格判断、确定性随机分组、分层随机、互斥实验、样本比例、保留组和跨端/跨批次一致分桶。
- 以已发布标签为输入的策略差异表达，包括“无标签基线”“使用指定标签”“使用标签与既有规则组合”等可审计变体。
- 策略建议、人工领取和实际动作的暴露记录；送达、响应、处理、转化/回收、投诉/退订、时效和人工成本等结果回流。
- 指标口径、最小样本/最短观察期、显著性或可信区间、护栏指标、异常告警、实验结论及推广审批记录。
- 实验工作台、详情页、结果看板、受试样本与排除清单、导出权限及全链路审计。

### 不纳入范围

- 本任务不建设新的标签生产、甲方实时同步、原始数据采集、消息/外呼通道或案件核心状态变更能力；仅消费已获授权、已审核且满足时效要求的数据、标签和执行结果。
- 本任务不以实验为由绕过甲方账号/接口白名单、额度、频控、数据用途限制、用户同意/退订、冷却期、投诉处置、人工复核或其他合规阻断规则。
- 本任务不允许以实验结果直接作出授信、定价、拒绝服务、处罚等高影响自动决定；若涉及高影响场景，只能做离线评估或经独立合规审批的人工辅助试点。
- 本任务不实现黑箱模型自动探索、动态多臂老虎机或自动扩大流量；后续如需引入，必须在本任务的审计、护栏、停止和人工审批框架下另行评审。

## 依赖与边界

- 依赖《数据延迟大 · 几乎没有打标动作》提供的数据版本、完整度、新鲜度、标签审核状态、迟到数据复核和审计能力。
- 依赖《标签粒度粗 · 不够准》提供标签定义、粒度、证据、适用范围、失效时间和消费边界；L0/待同步、草稿、待复核、撤销、过期或证据失效标签不得作为实验正式输入。
- 依赖《无人群分层》提供案件输入快照、分层规则、推荐动作、执行反馈及其硬性阻断；实验只改变经审批的策略差异，不改变基础数据准入与安全约束。
- 标签的“有效性”定义为相对既定基线策略的因果增量，不等同于标签覆盖率、相关性、模型分数、单组转化率或运营主观感受。

## 角色与权限

| 角色 | 权限 |
| --- | --- |
| 运营负责人 | 创建实验目标与策略草案；设置人群、指标、样本和观察期；提交启动、暂停、结束和推广申请。 |
| 策略/数据运营人员 | 配置标签依赖、分层维度、随机化方案、指标口径与回测；查看脱敏样本和统计结果；不得绕过审批直接发布。 |
| 复核/合规负责人 | 审批涉及敏感人群、触达策略、较高风险标签或例外的实验；确认护栏与停止规则；可紧急暂停。 |
| 案件运营人员 | 按分配的实验策略执行允许动作并如实回填结果；可报告异常，不得自行改组、改策略或篡改暴露记录。 |
| 数据接入人员 | 维护结果回流质量、延迟和异常补齐；不得修改实验业务假设或统计结论。 |
| 审计管理员 | 查询实验、分组、输入快照、策略暴露、结果、审批、导出和权限日志；无业务编辑权限。 |

## 实验对象与数据契约

### 实验最小定义

每个实验必须绑定不可变版本，并至少包含：

- 实验唯一键、名称、所属业务线、负责人、业务假设、目标业务问题、创建/审批/启动/结束时间及当前状态。
- 目标人群与排除条件：业务类型、案件状态、地域/渠道、创建或到期时间、数据质量条件、授权范围及不适用人群。
- 主指标、次指标、护栏指标、指标公式、归因事件、归因窗口、去重规则、缺失/迟到结果处理规则和判定阈值。
- 基线变体（A）和标签策略变体（B）的策略版本；两者允许差异必须显式列出，除经审批的标签及其直接规则外不得同时改变文案、渠道、频次、人员、时段或其他关键变量。
- 分流单位（默认案件唯一键）、分配比例、随机种子/分桶算法版本、分层维度、最小样本量、最短运行时长、最长观察期、启动/停止条件和互斥实验组。

### 输入资格与快照

- 进入分流前必须生成输入快照：案件唯一键、业务线、案件状态、数据版本、完整度、新鲜度、已发布标签及版本、标签证据时间、同意/退订和冷却状态、当前分层与适用策略版本。
- 只有数据完整、关键差异已解决、处于实验允许时效、标签已发布且未失效、并通过所有硬性合规和业务阻断的案件，才可成为合格受试对象。
- 不合格案件必须记录排除原因（如数据过期、标签待复核、无授权、已在互斥实验、命中冷却期、已完成/关闭、风险人工复核中），不得静默改分到任一组。
- 分流后源数据或标签发生更新时，保留原始入组快照；如更新触发安全阻断、标签撤销或案件状态不再可执行，立即停止后续动作并记录“中止/失效”，不得用新标签回写既有实验暴露。

## 分组与策略规则

### 对照与实验变体

| 变体 | 定义 | 约束 |
| --- | --- | --- |
| A：基线对照 | 使用当前已批准、且不消费目标标签的既有策略。 | 必须明确策略版本和正常业务动作，禁止以“不处理”伪造对照，除非业务和合规已批准保留组。 |
| B：标签策略 | 在同等准入、渠道、频控和执行能力下，使用目标标签驱动的策略差异。 | 目标标签、标签版本范围、条件、推荐动作和回退规则必须明确且可追溯。 |
| 可选 B2…Bn | 比较不同标签定义或不同标签驱动规则。 | 多变体需在启动前说明样本分配、比较关系、多重比较处理及互斥关系。 |

### 分流规则

- 默认按案件唯一键进行确定性哈希分桶；同一案件在同一实验版本、跨重试和跨页面访问中必须保持同组，除非该次实验已终止且新实验重新入组。
- 当案例在关键维度（例如业务类型、价值层、地区、渠道、入组日）上差异显著时，采用分层随机并记录分层字段及各组配额，避免单组集中高价值或高风险案件。
- 一个案件在任一时刻只能参与一个会影响同一渠道、同一目标指标或同一核心动作的互斥实验；系统在入组前检查冲突并记录拦截原因。
- 运行期间不得根据早期结果手工将特定案件换组、替换随机种子或调整样本比例；确需变更时须暂停并创建新版本/新实验，保留原实验数据和原因。
- 实验组策略无法执行时，按预定义的安全回退策略处理；回退不改变原始分组，且须将“建议暴露”“实际执行”“回退原因”分别记录，防止把未执行案件误计为标签效果。

## 功能需求

### 实验配置与审批

- 工作台支持创建草案、选择目标标签定义及允许版本、配置 A/B 策略、目标人群、排除条件、样本比例、分层维度、指标、观察期、护栏和停止规则。
- 启动前执行预检：标签可用性、数据质量、策略差异完整性、样本容量、实验冲突、结果事件可回流性、渠道容量、权限/同意/频控和审批状态；预检失败不得启动。
- 实验版本发布后配置不可直接覆盖。任何策略、标签版本范围、指标公式、分流算法、样本比例或观察期修改都必须形成新版本，并记录变更影响和审批人。
- 高风险标签、人群、触达方式或可能影响用户权益的实验必须增加复核/合规审批；紧急暂停可由授权人员执行，但恢复必须重新审批。

### 分流、执行与异常处置

- 系统在案件首次满足资格时完成分组并写入分组记录；队列和案件详情必须显示实验标识、分组、策略版本、入组时间、可执行状态和不暴露敏感标签值的解释。
- 策略引擎必须在每次动作前重检硬性阻断；实验分组不能覆盖退订、拒绝、频控、冷却期、数据过期、标签撤销、案件终结或人工暂停。
- 记录策略“被选中”的建议暴露、人员领取、实际触达/处理、失败、跳过、回退、取消和结果回流事件，并以事件时间线关联到实验、案件、标签版本和动作唯一键。
- 对结果数据迟到、重复、缺失、来源冲突或回流中断建立告警及待补齐队列；统计看板要区分“未发生结果”“尚在观察期”“结果缺失”和“无法归因”。

### 工作台与页面交互

- 实验列表默认展示实验名称/编号、目标标签、当前版本、状态、负责人、入组进度、观察期完成率、主指标当前值、护栏状态、最后更新时间；支持按业务线、状态、标签、负责人、创建/运行时间及风险等级筛选，并保留筛选条件用于导出。
- 新建实验采用分步表单：`业务假设 → 人群与标签 → A/B 策略差异 → 分流与样本 → 指标与归因 → 护栏与停止 → 审批预览`。每一步展示必填项、依赖校验结果和未解决风险；未完成前一步的关键字段不得进入提交审批。
- 策略差异页必须以并排方式展示 A/B 的渠道、动作、频控、时段、人员队列、文案/脚本、标签条件、回退方式和策略版本。除目标标签及审批允许的直接规则外，任何字段差异均以高亮和阻断提示显示，防止把多项变化误归因于标签。
- 详情页至少包含“概览、配置与审批、样本与分流、执行时间线、结果分析、告警与暂停、审计记录”页签；每个数字均可追溯至统计口径、数据截止时间和数据版本，不能只展示无口径的汇总值。
- 样本页默认只展示脱敏业务标识、入组/排除状态、分组、资格判断、标签可用状态、策略建议、执行状态、观察期状态和结果状态。查看标签证据、完整动作参数或导出明细时，必须进行权限校验并写入审计。
- 页面刷新、筛选切换或结果回流重算不得改变既有分组；对于已归档实验，页面只读，但允许按权限下载配置快照、汇总结果和审计证明。

### 告警、暂停与补救交互

- 告警按严重程度分为“提示、需关注、暂停建议、紧急暂停”，并展示触发指标、阈值、受影响变体/人群、开始时间、当前样本量、证据链接和处理时限；同一根因的重复告警应聚合，不能以大量重复通知掩盖风险。
- 触发自动暂停时，系统立即停止新入组和未执行的可选动作，保留已进入观察期样本；详情页须明确“自动暂停原因、停止生效时间、影响范围、已执行动作、待补齐事项和负责人”。
- 授权人员可提交人工暂停、恢复、提前结束或补救申请，但不能直接覆盖系统证据。恢复申请须列明根因、修复验证、剩余样本/观察期影响和重新预检结果，并经过与启动同级的审批。
- 对已执行但因标签撤销、同意状态变化、投诉、通道异常而不应继续的动作，系统生成受影响样本清单和补救任务；补救结果单独记录，不得删除原始建议或执行事实。

### 结果分析与决策

- 默认同时展示意向分析（按分组统计）与实际执行分析（按实际暴露统计），并明确实际执行分析可能受执行偏差影响；实验主结论以预先定义的意向分析口径为准。
- 展示各组入组数、合格率、排除数、建议暴露数、实际执行数、执行率、主/次指标、绝对差、相对差、置信区间或显著性结果、观察期完成率和数据缺失率。
- 支持按预定义分层维度查看结果异质性，但探索性切片必须标记为“探索结果”，不得替代主指标结论或被用来事后挑选有利样本。
- 仅在达到最小样本量、最短运行时长、完整观察期和数据质量阈值后给出“有效/无明显增益/结果不确定”的结论；任何早停必须匹配预定义的安全护栏或统计停止规则。
- 实验结束后形成决策记录：推广、继续观察、调整后重试、暂停或否决；推广须新建已批准策略版本并按灰度比例放量，不能直接把实验配置改为全量生产策略。

### 推广后的复核

- 被判定“有效”只代表在本实验人群、时间、渠道和版本下达到预注册标准，不自动外推至其他业务线、人群或标签版本；结论卡片必须展示适用边界和不可外推条件。
- 灰度推广需单独记录推广策略版本、灰度比例、目标人群、起止时间、监控指标、回滚阈值和审批人；推广数据与原实验数据分开存储和展示，避免把生产流量追加到实验样本中。
- 推广期间持续监控实验主指标对应的业务表现及全部护栏；若灰度结果与实验结论明显背离，自动建议回滚并创建复核记录，重点检查人群漂移、标签版本变化、执行能力和结果回流变化。

## 指标与停止规则

### 指标口径

| 类型 | 最低要求 |
| --- | --- |
| 主指标 | 与实验业务假设一一对应，例如规定归因窗口内的有效转化率、有效回收率或按案件的净收益；必须给出分子、分母、去重及归因规则。 |
| 次指标 | 用于解释机制，例如有效触达率、人工处理完成率、时效达成率、标签覆盖率和执行率；不得以次指标替代主指标判定。 |
| 护栏指标 | 监控负面影响，例如退订/投诉率、触达失败率、重复触达率、超时率、人工工时、成本、风险复核率及数据质量异常率。 |
| 质量指标 | 监控随机化和数据可信度，例如样本比例偏差、关键特征平衡、标签失效率、结果回流延迟、缺失率和跨实验冲突率。 |

### 统计判定与数据冻结

- 实验启动前必须预注册主指标的基线估计、最小可检测提升值、显著性水平或可信区间标准、检验方法、最小样本量计算参数、分层汇总方式及多变体比较校正方式；未填写的实验不得进入待审批。
- 主结论采用意向分析：分母为所有完成入组且符合原始资格的样本，并按首次稳定分组归属统计；即使后续未执行、执行失败或安全回退，也不得在主分析中随意移除。实际执行分析仅用于解释执行偏差和运营容量影响。
- 对结果迟到预留预注册的归因宽限期。宽限期结束后冻结本次分析数据集，迟到或修订事件进入“事后修订”队列，需生成修订版报告并保留原报告，不得静默改写历史结论。
- 结果缺失必须分别披露各组缺失数量、缺失原因、缺失率差异和可能影响；当缺失率、回流延迟或两组差异超过质量阈值时，只能给出“结果不确定”或按预设敏感性分析说明范围。
- 看板在样本量不足或观察期未完成时，只显示“运行中数据，不构成结论”；不得使用红绿涨跌、排行榜或“领先”文案诱导提前决策。探索性分层、事后指标和人工备注均与预注册主结论分区展示。

### 事件字段与关联要求

| 事件 | 产生时机 | 最低关联字段 |
| --- | --- | --- |
| `experiment_enrollment` | 案件首次通过资格并完成分组 | 实验/版本、案件脱敏键、资格快照版本、分组、分层值、分桶算法版本、入组时间、排除原因（如未入组） |
| `strategy_recommendation` | 系统选中策略并生成建议 | 实验/版本、案件键、分组、标签定义/实例版本、策略版本、建议动作、生成时间、幂等键 |
| `action_execution` | 人工或通道实际执行、失败、跳过、回退或取消 | 建议幂等键、动作唯一键、执行状态、执行/失败时间、失败或回退代码、执行主体、通道 |
| `outcome_attribution` | 结果事件到达并完成归因 | 结果事件唯一键、案件键、关联动作键、结果类型、业务发生时间、接收时间、归因窗口、来源版本、修订标识 |
| `experiment_control` | 审批、预检、暂停、恢复、结束、推广或导出 | 实验/版本、操作类型、操作人/角色、原因、前后状态、审批/告警关联键、操作时间 |

- 所有事件必须支持至少一次投递下的幂等去重：以事件来源、来源事件唯一键和版本作为去重依据；冲突记录进入待复核，不得以最后到达的一条事件直接覆盖已归因结果。
- 事件时间、接收时间和处理时间必须分列存储并统一时区；分析默认以业务发生时间归因、以数据截止时间控制可见性。无法确定业务发生时间的事件不得进入主指标，须作为数据质量异常披露。

### 启动、暂停与结束

- 启动条件：实验已审批；输入数据、目标标签、对照/实验策略和结果事件均可用；样本容量与渠道/人工产能满足预设门槛；不存在未解决的合规风险或互斥冲突。
- 自动暂停条件：任一护栏超过审批阈值、出现严重合规/安全事件、关键标签大规模撤销或失效、结果回流中断超过阈值、随机分流异常、策略执行异常或数据质量无法支撑判定。
- 正常结束条件：达到预设最小样本、最短运行时长和全部受试样本的归因窗口；若未达到数据质量要求，结论为“不确定”，不得包装为无效或有效。
- 提前结束必须记录触发规则、时间、影响样本、已完成观察期比例、审批人和后续补救；不得因单次短期波动或运营偏好提前宣告标签有效。

### 默认阈值配置原则

- 系统不在需求层预置通用的业务提升、投诉或成本数值阈值；每个业务线必须在审批前填写经负责人确认的阈值、数据来源和计算周期，未配置时禁止启动。
- 对分流偏差、回流中断、标签失效、权限/同意变化等通用质量风险，系统提供可配置阈值和默认“停止新入组、人工复核”的保守动作；业务线可收紧但不得在运行中放宽。
- 阈值比较应明确分母、窗口、最小样本保护和连续触发次数，避免小样本偶发波动触发或掩盖风险；告警评估频率、静默期和升级对象均纳入审批快照。

## 状态流转

`草案 → 待审批 → 预检通过 → 运行中 → 观察期结束 → 分析中 → 已结束/已归档`

- `草案`：可编辑，尚未提交审批。
- `待审批`：配置冻结，等待运营及必要的复核/合规审批。
- `预检通过`：检查通过，待在批准时间窗口启动；预检失效时退回草案。
- `运行中`：允许符合资格的案件稳定入组并执行；可因护栏、异常或授权变化转为“已暂停”。
- `已暂停`：停止新入组和后续可选动作，保留已入组样本观察和审计；恢复须重新预检和审批。
- `观察期结束`：停止新入组，等待既有样本完成规定归因窗口与结果回流。
- `分析中`：按预注册口径生成结论及决策建议；数据缺失需标注不确定性。
- `已结束/已归档`：结论、审批、策略推广或否决记录冻结，只读可审计。

## 审计与合规要求

- 全量记录实验配置与版本、审批、预检结果、资格判断、排除原因、分组算法版本和种子标识、输入快照、标签/策略版本、每次建议与实际执行、结果事件、统计任务、导出和权限变更。
- 展示、导出和分析采用最小必要原则：默认展示聚合和脱敏信息；含业务唯一键或敏感字段的样本明细仅限具备权限的人员，并记录用途和下载审计。
- 所有实验结果都必须可回放至入组当时的标签证据和策略版本；禁止用当前标签、当前策略或后补结果覆盖历史实验事实。
- 对标签撤销、数据主体请求、授权到期、投诉或重大执行异常，应能定位受影响实验、样本、已执行动作和推广策略，并按既定流程暂停、复核或补救。

## 验收标准

- 可创建并审批以“是否使用指定已发布标签”为唯一核心差异的 A/B 实验；系统会校验标签状态、适用范围、数据时效、策略差异、权限、互斥和结果回流能力。
- 同一案件在同一实验版本中始终进入同一分组；按配置维度可验证各组样本分布，且不合格、冲突或被阻断案件均有可查询排除原因。
- 每个入组样本可追溯入组快照、标签/策略版本、建议暴露、实际执行、回退/失败原因和归因结果；标签更新或撤销不会改写历史入组证据。
- 主看板同时显示各组样本、执行率、主/次/护栏指标、绝对与相对差、统计不确定性、观察期完成率和数据缺失；不会将未执行或未满观察期样本错误计为负向结果。
- 达到护栏、数据质量、分流异常或合规停止规则时，系统自动停止新入组并告警；恢复和推广均需重新审批，且推广以独立的灰度策略版本执行。
- 实验结束后可按预注册指标形成“有效、无明显增益或结果不确定”的结论，附带样本条件、限制、审批和后续决策；没有达到门槛时不能宣称标签有效。
- 任意审计用户可查询从实验定义到最终推广/否决的完整操作链路，且日志和导出不泄露超出权限范围的敏感原始数据。
- 创建页能阻止未定义唯一核心差异、未指定结果回流、未完成样本/观察期计算或未配置停止规则的实验提交审批；A/B 策略差异在提交前可视化核对并保留快照。
- 详情页可从任一聚合指标下钻到对应脱敏样本、入组快照、建议/执行事件和归因状态；数字均标注统计口径、数据截止时间及是否已冻结，权限不足时仅返回聚合结果。
- 自动暂停、人工恢复、提前结束和灰度推广均产生不可篡改的状态记录、审批记录和影响样本清单；已执行动作的补救结果可追溯但不覆盖原始事实。
- 数据截止时间后收到的修订或迟到事件会生成可审计的修订分析版本；主报告不会被静默覆盖，并能比较修订前后的结果差异与原因。

## 待确认项

- 本业务中最优先验证的标签、对应业务假设、基线策略和可允许的策略差异分别是什么？是否只验证“有/无标签”，还是也要比较不同标签定义？
- 主指标应使用有效触达、转化、回收、净收益还是其他口径？归因窗口、去重规则、目标提升值、最小样本量和统计判定标准由谁确认？
- 哪些业务类型、人群、渠道、地区和案件状态可进入实验？哪些敏感/高风险人群只能离线回测或必须人工审批？
- 当前是否可稳定回流送达、响应、处理、转化、投诉/退订、成本和人工工时？各事件的唯一键、延迟、修订和权威来源是什么？
- 是否已有实验平台、统一分桶服务或策略引擎？若无，案件唯一键的稳定性、哈希算法、跨系统分组传递和并发幂等要求是什么？
- 护栏阈值、紧急暂停权限、告警通知对象、恢复条件和已执行动作的补救 SOP 分别是什么？
- 实验明细、输入快照、标签证据、动作日志和结果数据的保留期限、脱敏规则、访问边界及导出审批要求是什么？
- 是否需要为每个业务目标提供标准化的样本量计算器、指标模板和默认质量阈值？若需要，哪个团队维护模板版本并对例外负责？
- 当前策略、通道和人工处理系统能否稳定返回“建议生成、实际执行、失败/回退、取消”四类事件？如不能，首期是否限制为可完整记录执行链路的渠道？
- 对迟到或修订结果，业务更需要“冻结后仅出修订报告”还是“在明确版本下更新正式报告”？两种方式的审批和对外沟通责任人分别是谁？
