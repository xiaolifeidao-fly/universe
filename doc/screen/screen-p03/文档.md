# 标签粒度粗 · 不够准

## 背景

- 当前第一阶段只能基于已到达且已确认的有限字段生成粗粒度标识，例如业务类型、案件状态、基础时效、数据完整度和人工处理状态。这些标签可支持基本分流，但无法准确表达客户实时状态、最新意向、可触达性或更细的业务属性。
- 甲方实时数据同步尚未打通。若把历史快照、推测结果或缺失字段包装成细粒度标签，会误导后续人群分层、触达和人工处置；因此必须明确区分“已证实的粗标签”“待同步的细标签”和“不可推断的信息”。
- 前置任务《数据延迟大 · 几乎没有打标动作》已定义数据准入、版本、审核、迟到数据复核和补齐闭环。本任务在此基础上定义标签粒度、证据要求和从第一阶段过渡到实时同步阶段的规则，不替代数据采集或甲方接口建设。

## 目标

- 第一阶段交付可稳定使用、定义明确、可追溯的粗粒度标签集，确保标签只陈述已有数据能够证明的事实。
- 为每个待建设的细粒度标签预先定义业务语义、最小实时字段、来源、刷新时效、质量门槛、失效规则和消费边界，使甲方同步打通后可以受控启用。
- 在工作台、接口和下游消费中明确展示标签粒度、数据时间、数据版本、证据状态与适用性，避免将粗标签误认为精确画像。
- 当实时数据到达、延迟、缺失、冲突或撤回时，自动触发标签重算、复核或降级，并保留完整历史与审计证据。

## 范围

### 纳入范围

- 粗粒度与细粒度标签的分级模型、标签定义、版本、适用范围、证据字段、标签状态和生命周期管理。
- 第一阶段可发布的粗标签集，包括基础业务分类、流程状态、时效区间、数据质量、授权/触达限制及人工处置状态等事实型标签。
- 细粒度标签的“待同步”定义与启用门槛，包括甲方实时字段映射、同步延迟、完整度、冲突处理、回填和重算策略。
- 标签工作台与对外接口的展示/返回规范：粒度级别、证据时间、刷新时间、版本、置信状态、失效时间和不可用原因。
- 下游人群分层、触达建议和人工任务对标签粒度的消费约束、人工例外与审计记录。
- 标签覆盖率、实时性、准确性、冲突率、待同步积压和降级次数等运营指标。

### 不纳入范围

- 在本任务中新增、改造或绕过甲方实时接口、账号授权、白名单、调用额度或频控策略；实时同步通道由独立的数据接入任务建设。
- 根据历史行为、规则猜测或模型推断直接生成并发布客户实时意向、实时联系方式、实时资产/风险等细粒度事实标签。
- 以标签直接执行外呼、消息发送、业务状态变更、授信、定价、拒绝服务或其他高影响决定；下游能力须独立进行权限、同意状态与合规校验。
- 将人工备注、未验证导入数据或待复核标签静默提升为正式细粒度标签。

## 角色与权限

| 角色 | 权限 |
| --- | --- |
| 运营负责人 | 审批标签分级、定义、适用范围、服务时限和启停策略；审批高风险例外。 |
| 策略/数据运营人员 | 维护标签字典草案、字段映射、质量阈值和回测结果；无权自行发布细粒度标签。 |
| 打标员 | 基于可见证据创建或维护允许范围内的粗标签，保存草稿并提交复核；不得把缺失信息补写为细粒度事实。 |
| 复核员 | 审核标签证据、冲突和降级/恢复结果；通过、驳回或要求补齐。 |
| 数据接入人员 | 维护已获授权的同步映射、批次状态和异常补齐事项；不得修改标签业务定义或绕过准入规则。 |
| 审计管理员 | 查询标签定义、版本、输入快照、发布、重算、撤销、人工例外和导出日志；无业务编辑权限。 |

## 标签分级与数据契约

### 粒度级别

| 级别 | 名称 | 定义与示例 | 可否作为下游强决策依据 |
| --- | --- | --- | --- |
| L1 | 粗粒度事实标签 | 由当前已确认字段直接得出的类别或状态，例如“案件处理中”“数据 T+1”“资料待补齐”“禁止触达”。 | 可以，但仅在标签定义声明的业务范围内使用。 |
| L2 | 细粒度实时标签 | 依赖甲方实时同步、字段完整度与新鲜度的精确属性，例如“最新可联系状态”“实时业务阶段”“最近一次确认意向”。 | 仅在已发布、未过期且通过质量门槛时可以使用。 |
| L0 | 未知/待同步 | 细粒度事实所需数据未到达、超时、冲突、待确认或无授权来源。 | 不可以；必须显式返回不可用原因。 |

### 标签定义必备字段

每个标签定义至少包含：

- 标签编码、名称、所属业务线、适用业务类型、粒度级别（L1/L2）、标签值类型和互斥/可共存规则。
- 业务语义、允许表达的事实边界、禁止推断的内容、下游可消费场景与禁止消费场景。
- 所需源字段、授权来源、字段映射版本、输入完整度阈值、数据新鲜度服务时限和标签失效时间。
- 计算/人工创建规则、证据快照要求、审核级别、发布条件、重算触发事件、降级/撤销规则和责任角色。
- 标签定义版本、生效/停用时间、变更说明和审批记录。

### 标签实例必备字段

每个标签实例至少绑定业务唯一键、标签定义及版本、标签值、粒度级别、状态、来源类型、输入数据版本/批次、源业务发生时间、数据到达时间、计算或创建时间、最近验证时间、失效时间、证据摘要、操作人/规则版本与审核记录。敏感原始内容按最小必要原则脱敏展示，不得复制到标签名称、原因或导出字段中。

## 第一阶段：粗粒度标签可用

### 发布规则

- 仅发布 L1 粗粒度事实标签。标签必须由当前已确认的字段直接支持，且输入满足前置任务定义的数据完整度、来源可追溯和审核要求。
- 对实时事实没有数据、数据超过定义时效、字段冲突或尚未获得甲方授权来源时，必须生成或保留 L0“未知/待同步”状态；不得用“否”“低”“无意向”“不可联系”等确定性标签替代未知。
- 粗标签名称和说明不得暗示精确画像。例如以“基础时效：T+1”“当前流程：待处理”替代“客户紧急”“客户不活跃”等未经实时证据支持的结论。
- 每个标签在工作台和接口中必须返回 `granularity`、`evidenceAt`、`refreshedAt`、`dataVersion`、`status`、`expiresAt` 与 `unavailableReason`（如适用）。

### 下游消费规则

- 人群分层仅可把 L1 用于基础分流、数据质量阻断、服务时限排序和人工复核优先级；不得仅依据 L1 推导客户即时意向、实时可联系状态或精确价值等级。
- 触达、人工任务或其他下游模块收到 L0 时，必须停止依赖该细粒度维度的自动建议，并显示“待甲方实时同步/待确认”的原因和下一步处理路径。
- 下游必须记录所消费的标签定义版本、实例版本和证据时间；标签撤销、过期或降级后，相关建议须重新评估，不得继续使用旧结论。

## 第二阶段：甲方实时同步打通后启用细粒度标签

### 启用前置条件

单个 L2 标签只有同时满足以下条件才可以发布：

- 甲方已完成该标签必需字段的授权、接口/文件映射、唯一键关联和稳定的增量或实时同步；未授权字段不得进入标签计算。
- 已配置字段字典、枚举值、空值语义、时区、业务发生时间、去重/幂等规则、数据版本和错误处理，并通过样本对账。
- 同步延迟、字段完整度、关联成功率和冲突率达到标签定义的服务门槛；阈值不达标时仅保留 L0 或降级到仍被证据支持的 L1。
- 标签规则完成回测、灰度、复核与运营负责人审批；规则、字段映射和阈值均以版本化方式发布。

### 同步、重算与冲突处理

- 实时事件或增量数据到达后，以业务唯一键和源版本幂等合并，更新输入快照并只重算受影响的标签；重复事件不得重复生成实例或触发重复下游动作。
- 数据更新、补齐、纠错、撤回、授权失效、延迟超时、字段冲突和规则版本变更均应触发相应标签的重算、待复核、撤销或降级，并记录触发原因。
- 同一字段来自多个来源且值冲突时，按标签定义中的来源优先级、业务发生时间和确认状态处理；无法消解时标签状态为“待复核”，不得自动选择有利于业务的一方。
- L2 超过新鲜度服务时限后自动失效或降级为 L0/L1，直到有新的合格实时数据；历史实例保留以支持审计，但不得作为当前事实输出。
- 对迟到事件，须按源业务发生时间与到达时间更新，并评估是否影响已产生的分层/触达建议；影响高风险或已执行动作时进入人工复核队列。

## 状态机与工作台要求

### 标签实例状态

`草稿` → `待复核` → `已发布` → `已过期/已撤销/已降级`；数据缺失、同步未完成或质量不达标时使用 `待同步`。只有 `已发布` 且未过期的实例可以作为当前事实被下游消费。

- L1 可由符合权限的人工或规则创建，经适用审核后发布。
- L2 在同步与质量门槛满足前必须保持 `待同步`，不能通过人工确认绕过实时字段要求；如确有人工核验流程，应作为独立、有时效的人工事实标签，不能伪装为实时同步标签。
- 页面同时展示“当前可用标签”和“待同步细粒度维度”，后者须包含缺失字段/来源、责任方、最近同步状态、预计/约定时限（如已配置）及人工补齐入口。
- 标签详情应支持查看定义版本、粒度、输入快照摘要、证据时间线、发布/复核记录、失效原因、关联下游使用记录与重新计算结果。

## 指标与告警

- 按业务线、标签定义和粒度统计 L1/L2/L0 覆盖率、待同步量、发布量、过期量、降级量、复核积压和人工例外数量。
- 监控实时同步延迟、字段完整度、关联成功率、去重命中率、冲突率、重算耗时、标签新鲜度达标率及下游因 L0/L2 失效而阻断的次数。
- 当关键 L2 标签连续超过服务时限、同步中断、完整度/关联率低于门槛、冲突率异常或自动降级激增时，告警至数据接入负责人和运营负责人；告警应携带受影响业务范围、标签定义版本、起始时间和处置状态。
- 所有指标均区分“数据未同步”“数据质量不达标”“规则未发布”“权限/授权受限”和“人工待复核”，避免用单一覆盖率掩盖问题。

## 审计与合规要求

- 每次标签创建、修改、发布、重算、降级、撤销、人工例外和下游消费都必须记录业务唯一键、定义/规则/映射版本、输入版本、操作主体、时间、原因和审批链路。
- 标签仅使用已授权且与用途相符的数据；权限收回、接口停用或数据保留期届满时，应停止相关 L2 计算并按规则失效或删除实例。
- 对外展示、导出和运营看板遵循最小必要和脱敏原则；严禁在标签值、理由或自由文本中泄露完整敏感原始数据。

## 验收标准

- 系统可维护 L1、L2、L0 三类标签定义，并能为每个定义配置字段来源、粒度、时效、质量门槛、版本、下游消费边界和降级策略。
- 第一阶段只能发布被当前证据直接支持的 L1 标签；缺少实时字段时，页面和接口均返回 L0/待同步及明确原因，不生成伪精确标签。
- 每个返回给下游的标签均能查询粒度、定义版本、输入数据版本、证据时间、状态和失效时间；下游能拒绝过期、撤销、待复核和待同步标签。
- 甲方实时同步达标后，L2 标签可在已配置的字段、延迟、完整度、关联率和审批门槛下灰度并正式发布；未达标时自动保持/回退为 L0 或受支持的 L1。
- 数据更新、迟到、撤回、冲突、规则变更和授权失效能触发可追溯的重算、复核、撤销或降级，且不会产生重复实例或重复下游动作。
- 工作台能同时展示当前粗标签和待同步细维度，并可定位缺失原因、责任方、同步状态、标签证据和下游影响。
- 运营看板与告警可区分同步问题、数据质量问题、规则问题、权限问题和人工复核问题，并支持按标签定义和业务线追踪。

## 待确认项

- 第一阶段已稳定到达并经业务确认的字段清单是什么？各字段的枚举、空值语义、业务发生时间和可用时效分别为何？
- 哪些细粒度标签是业务优先级最高的？每个标签对应的甲方实时字段、授权接口/文件、更新频率、目标延迟和责任方是什么？
- 甲方实时同步采用事件、轮询增量还是文件方式？是否提供业务唯一键、变更游标、源版本、撤回标记和源业务发生时间？
- L2 标签的完整度、关联成功率、延迟、冲突率、灰度比例和回测准确性门槛分别是多少？由谁审批正式发布？
- 字段冲突时的权威来源优先级、人工裁决角色和处理时限是什么？迟到数据影响已触达动作时，补救与复核 SOP 是什么？
- L0/待同步在不同下游场景中的默认行为是阻断、转人工还是使用限定的 L1 规则？对应的服务时限和容量配置是什么？
- 标签、输入快照、同步日志和下游消费记录的保留期限、脱敏规则、访问边界及数据主体权利处理流程是什么？
