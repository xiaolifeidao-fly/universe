# 管理端仪表盘统计修正

## 已修正

- 小时汇总：巡检原来包含当前未结束的小时，过早写入标记后不再更新，导致 token、消费和共享端收益同时少算。现在只处理已结束且经过宽限期的小时；读取和巡检均拒绝提前生成的标记，按原始流水重算，覆盖旧派生数据。
- token：混合新旧计量时，总 token 行可能只覆盖部分记录。与输入、输出、缓存四桶合计比较，避免漏掉分项；缓存写入合计和 TTL 分项不重复累加，推理不重复计入输出。
- 请求数：新增今日创建请求的总数、成功、失败、取消、过期、在途统计。成功数取请求状态，计量调用保留在用量表中，两者不混称。
- 机器：封禁机器不再计入在线或额度供给；没有开启共享的机器不再当作无限额度机器。
- 快照：按实际使用的额度快照判断过期，缺失或任意过期快照触发告警，不再用最新一条快照掩盖其他旧快照。
- 金额：最多展示六位小数，保留微元精度；使用端和共享端金额继续从历史结算账本读取。
- 兼容：旧服务端缺少请求统计时不显示假的成功数；缺少 tokenBuckets 时不崩溃。

## 统计边界

日期沿用服务端时区。请求按创建时间统计；token 和金额按计量/结算流水写入时间统计，跨日时不应按请求创建日直接对账。

“使用端金额”是结算应收，不是充值现金流，也不是扣除退款后的净收入。“毛利”是结算应收减共享端结算，不含邀请奖励、退款和支付费用，不等同于净利润。

额度表跨单位合计是授权计量之和。不同单位可能重叠，也不是上游订阅的真实剩余 token；判断具体额度应查看分单位明细。后续若要运营净收入、退款和扣款差异，需增加独立资金对账统计，不应把这些混入现有结算毛利。

## 验证

回归测试覆盖提前封口的标记失效、巡检不写当前小时、旧汇总金额和 token 被原始流水替换、混合旧数据、TTL 去重、请求状态对账和封禁机器统计。

金额恢复用固定测试数据验证，不代表已核对线上数据库。上线服务后，管理端刷新将自动重算访问范围内过早封口的小时；未执行线上部署或账本修改。
