# 实现本机爬虫客户端基础运行能力：需求梳理

## 1. 任务目标与本阶段结论

本任务交付一个可安装在授权用户 Windows 电脑上的本机采集客户端基础运行时（下称“客户端”）。客户端在用户明确安装、授权和可见控制的前提下，能够读取本机非敏感配置和受保护凭证，按已验证策略调度采集任务，执行模拟采集，记录本地状态、错误和日志，并在可恢复网络故障后有限重试和受控停止。

本阶段已根据前置任务 `deployment-e89f2b122a` 的客户端—平台对接方案和当前仓库现状完成需求基线梳理。当前仓库仅包含 Go 服务端和 Next.js 控制台，**不存在可复用的本机采集客户端、浏览器自动化运行时、端侧任务 API 或生产采集适配器**；后续开发应新增独立的 `client/collector` Go 模块，不得把宿主进程、浏览器依赖或本地采集状态混入 `client/web` 或 `server/`。

本任务只实现通用运行能力和模拟适配器，不实现甲方站点的登录、页面解析、采集规则、反爬绕过、验证码处理、代理轮换、批量账号操作或平台业务数据入库。

## 2. 前置输入与强制边界

### 2.1 继承的对接约定

后续实现必须继承 `doc/deployment/deployment-e89f2b122a/文档.md` 中已定义的以下契约：

- 客户端以单一宿主进程运行，同一安装实例仅允许一个活跃进程；第二实例必须明确退出并写入本地事件。
- 平台目标接口基路径为 `/api/collector/v1`，任务以 `taskId`、`attemptId`、`leaseId`、`leaseExpiresAt`、`policyVersion`、`adapterKey` 等字段租约下发；尚未实现的平台接口不得由本任务临时改写服务端生产接口。
- 任务执行前必须比对 `bizLine`、`adapterKey`、`policyVersion`、操作类型、字段白名单和本机能力；不匹配时回传或本地记录 `TASK_POLICY_MISMATCH`，不得执行。
- 凭证仅允许存入 Windows Credential Manager / DPAPI 等操作系统受保护存储；配置文件、命令行、日志、转储和任务数据库中不得出现访问令牌、刷新凭证、Cookie、密码或验证码。
- 客户端只能执行经平台策略和本机用户授权的操作；遇到验证码、二次验证、站点拒绝访问、策略过期或设备吊销时必须停止自动操作，不得规避限制。

### 2.2 本任务范围

| 范围 | 本任务必须交付 |
| --- | --- |
| 启动与生命周期 | CLI/服务宿主入口、单实例锁、配置校验、启动/停止、优雅退出和退出码。 |
| 配置与安全存储 | 非敏感配置加载、环境变量覆盖、凭证存取抽象及 Windows 安全存储实现。 |
| 调度与执行 | 本地持久化队列、串行任务调度、任务租约抽象、执行器封装、模拟采集适配器。 |
| 可观测性 | 结构化轮转日志、可查询的任务状态/错误/事件、本地状态查询命令或只读 HTTP 诊断入口。 |
| 韧性 | 可分类失败、有限次数指数退避、网络恢复重试、停止新任务、受控取消。 |
| 扩展性 | 站点适配器注册表、稳定接口、能力声明和模拟适配器示例。 |

### 2.3 明确不在范围内

- 不实现任何具体甲方、WhatsApp 或第三方站点的页面选择器、账号登录、浏览器用户目录读取、Cookie 导出或数据解析规则。
- 不建设平台侧设备激活、策略签名、任务拉取、结果接收、租约、业务入库或管理控制台；客户端仅通过可替换的 `TaskSource` / `ResultReporter` 边界与其对接。
- 不做静默安装、不可见自启动、提权、远程桌面控制、键盘记录、屏幕录制或绕过网站服务条款、访问控制和频率限制的能力。
- 不将真实采集内容、完整 HTML、网络载荷、截图、账号资料或敏感诊断写入本地日志、SQLite 状态库或模拟结果。

## 3. 目标运行形态与目录约定

### 3.1 首期支持矩阵

首期运行目标固定为 **Windows 10/11 x64、当前登录用户上下文**。客户端以用户可见的命令行程序和用户级受管启动方式运行；不要求管理员权限。macOS/Linux 的实现可保留接口和交叉编译条件，但不作为本任务验收平台。

建议新增独立 Go 1.21 模块和以下逻辑边界：

```text
client/collector/
  cmd/collector-host/        # start、stop、status、run-once 等入口
  internal/bootstrap/        # 配置、依赖装配、单实例与生命周期
  internal/config/           # 文件、环境变量、校验、脱敏展示
  internal/securestore/      # Windows 凭据库/DPAPI 与测试替身
  internal/scheduler/        # 队列、状态机、取消、退避、租约时钟
  internal/runtime/          # TaskSource、ResultReporter、执行器与 HTTP 客户端
  internal/store/            # SQLite 任务、尝试、事件、设置的单写仓储
  internal/adapter/          # 适配器注册表、模拟适配器
  internal/observability/    # JSON 日志、轮转、诊断查询
  configs/collector.example.yaml
```

首期可使用 SQLite 作为单进程本地状态库；数据库只能由 `internal/store` 写入。运行数据目录必须由配置解析为当前用户可写路径，默认建议为 `%LOCALAPPDATA%\\UniverseCollector`，其中 `state/collector.db` 保存任务状态，`logs/` 保存轮转日志，`run/` 保存实例锁和运行期标识。安装目录及仓库不得写入运行数据、真实配置或凭证。

### 3.2 进程命令与退出行为

| 命令 | 行为 | 验收用途 |
| --- | --- | --- |
| `collector-host start --config <path>` | 加载配置、取得实例锁、恢复未完成任务、启动调度循环，前台运行至收到停止信号。 | 验证正常启动与守护运行。 |
| `collector-host run-once --config <path>` | 完成一次拉取/模拟入队和调度空转检测后退出。 | 自动化测试和模拟采集演示。 |
| `collector-host status --config <path>` | 仅读取本地状态库，输出实例、队列、最近任务、错误和重试摘要；不得启动执行器。 | 本地查询可观测性。 |
| `collector-host stop --config <path>` | 向同一用户会话中的实例发出停止请求；实例在安全点停止新源站动作、持久化状态并退出。 | 验证受控停止。 |

`start` 收到 `SIGINT`、`SIGTERM`、Windows 控制台关闭事件或 `stop` 请求后进入 `stopping`：立即停止领取和启动新任务，向正在执行的执行器传递取消上下文，等待至多配置的 `shutdownGracePeriodSeconds`（默认 30 秒），持久化任务检查点/取消原因，关闭数据库和日志后退出。超时必须以非零退出码退出，并留下 `shutdown_timeout` 事件；不得强杀浏览器或留下不明任务状态。

## 4. 配置与本地安全存储

### 4.1 配置优先级和字段

配置优先级固定为：**命令行显式路径 → YAML 文件 → `COLLECTOR_` 前缀环境变量 → 安全默认值**。不存在配置、YAML 格式错误、未知关键配置、路径不可写或值超出范围时，进程应在开始调度前失败，并只打印字段名和校验原因。

`configs/collector.example.yaml` 只提供无敏感示例，至少包含：

```yaml
runtimeDir: "%LOCALAPPDATA%\\UniverseCollector"
mode: simulation
apiBaseUrl: "https://collector-api.example.invalid/api/collector/v1"
deviceId: "local-simulator"
tenantId: "first-party-pending"
bizLine: "whatsapp"
pollIntervalSeconds: 60
maxConcurrentTasks: 1
shutdownGracePeriodSeconds: 30
logLevel: "info"
logRetentionDays: 14
logMaxSizeMiB: 20
resultRetentionHours: 72
retry:
  maxAttempts: 5
  initialDelaySeconds: 30
  maxDelaySeconds: 7200
```

- `mode` 仅支持 `simulation` 和未来的 `platform`；本任务默认 `simulation`，避免未实现平台契约时产生伪生产调用。
- `maxConcurrentTasks` 首期必须为 `1`；配置大于 `1` 应拒绝启动，而不是暗中改变并发语义。
- `apiBaseUrl` 在 `platform` 模式必须为 HTTPS，且不得包含用户名、密码、查询参数或片段；`simulation` 模式可不发起网络连接。
- `deviceId`、`tenantId`、`bizLine`、适配器允许列表和日志等级属于非敏感标识；日志输出仍应遵循脱敏规则。

访问令牌、刷新凭证和站点授权材料只通过 `CredentialStore` 以引用名读取。Windows 实现使用当前用户范围的 Credential Manager 或 DPAPI，测试/开发替身只允许在显式测试构建中使用，禁止把文件型明文实现注册为生产默认值。

### 4.2 本地数据保护与保留

| 数据 | 存放位置 | 保护和保留 |
| --- | --- | --- |
| 凭证 | OS 安全存储 | 不写入 SQLite/日志；吊销、卸载或明确清除时删除。 |
| 任务元数据和状态 | `state/collector.db` | 仅保存任务标识、策略版本、允许字段摘要、状态、错误码、次数、时间、检查点摘要；不保存原始页面和敏感结果。 |
| 待上报结果摘要 | 加密状态库或受保护本地队列 | 仅字段白名单结果；确认成功后删除，最长 `resultRetentionHours`。 |
| 日志和事件 | `logs/` 与状态库事件表 | 结构化脱敏日志；默认保留 14 天且按 20 MiB 单文件轮转，超出保留限制先删最旧文件。 |

## 5. 核心模型、状态机与持久化

### 5.1 必要实体

本地状态库至少维护以下实体，并为 `task_id`、`attempt_id`、`status`、`next_retry_at`、`updated_at` 建立查询索引：

| 实体 | 关键字段 | 用途 |
| --- | --- | --- |
| `tasks` | `task_id`、`attempt_id`、`lease_id`、`adapter_key`、`operation`、`policy_version`、`status`、`lease_expires_at` | 当前任务的最新可恢复状态。 |
| `task_attempts` | `attempt_id`、`attempt_no`、`started_at`、`finished_at`、`error_code`、`error_stage` | 每次本地执行/重试的审计摘要。 |
| `task_events` | `event_id`、`task_id`、`level`、`event_type`、`safe_message`、`occurred_at` | 状态转换、错误、停止和重试的查询记录。 |
| `settings` | `key`、`value`、`updated_at` | 无敏感运行元数据，如上次成功策略版本、停止请求序列。 |

所有状态转换、尝试计数、下一次重试时间和事件写入必须在同一个本地事务中完成，避免异常重启后出现“已执行但无记录”或“无限重试”的状态漂移。

### 5.2 客户端状态机

```text
queued → validating → running → reporting → succeeded
                        │            └──────→ partial_succeeded
                        ├→ retry_wait → validating
                        ├→ blocked
                        ├→ failed
                        └→ cancelled
```

- `queued`：任务已从模拟源或平台接收并持久化，尚未开始源站操作。
- `validating`：校验策略、适配器、任务有效期、租约、允许字段和本机运行环境。
- `running`：适配器在带取消上下文和截止时间的执行器中工作；首期同一时刻最多一个任务。
- `reporting`：仅对 `platform` 模式上报白名单结果或终态。网络暂不可用时转 `retry_wait`，不得丢弃未确认的最小结果摘要。
- `succeeded` / `partial_succeeded`：终态成功；部分成功必须写入条目计数和受限错误摘要。
- `blocked`：需要人工操作、策略确认、验证码/二次验证或授权不足；默认不自动重试。
- `failed`：不可恢复、租约过期、策略不匹配或达到最大重试次数后的终态。
- `cancelled`：本机用户、平台撤销或受控停止导致的终态；停止期间不得将尚未开始的 `queued` 任务误标成功。

进程重启时，`running`、`validating`、`reporting` 状态必须转换为 `retry_wait` 或 `failed`：租约仍有效且错误类别可恢复时以 `PROCESS_INTERRUPTED` 进入一次受限重试；租约已过期或不能证明任务仍可执行时标记 `TASK_LEASE_EXPIRED` / `failed`。不得自动重复可能已产生外部副作用的操作，除非适配器声明该操作可幂等重放。

## 6. 调度、执行和失败重试

### 6.1 调度规则

调度器应在客户端处于 `running`、存在有效本地策略、未收到停止请求且没有活跃任务时执行一次循环：恢复到期的 `retry_wait` 任务优先于领取新任务；没有待重试任务时，`simulation` 模式从本地模拟源拉取，`platform` 模式经 `TaskSource` 调用 `/tasks:pull`。每次最多接收并开始一个任务。

任务开始前必须完成以下门禁：单实例锁有效、适配器已注册、`adapterKey` 与任务相符、策略未过期、字段白名单通过、租约未到期、操作已在适配器能力集中声明、剩余租约大于最小执行窗口。任一门禁失败均不得调用浏览器或请求执行器。

执行器分为 `RequestExecutor` 和可选的 `BrowserExecutor` 两类端口；宿主只依赖接口，不依赖某一浏览器厂商或具体自动化库。模拟适配器不启动浏览器，使用可控的延迟、成功、网络失败和不可重试失败场景来验证调度流程。真实站点适配器后续选择经安全评审的请求或浏览器实现，并必须接收 `context`、任务截止时间、频率限制和取消信号。

### 6.2 失败分类和退避

错误必须归一为稳定错误码，并在任务、尝试、日志和查询输出中使用相同错误码。首期最低支持：

| 错误码 | 类别 | 客户端动作 |
| --- | --- | --- |
| `NETWORK_UNAVAILABLE` | 可恢复网络异常、超时、连接重置 | 记录失败，按退避策略转 `retry_wait`。 |
| `SOURCE_UNAVAILABLE` | 授权源站 5xx 或临时不可用 | 按退避策略转 `retry_wait`，并服从策略频率上限。 |
| `POLICY_EXPIRED` | 本地策略不存在、签名无效或已过期 | 停止新任务；仅在刷新到有效策略后恢复。 |
| `TASK_POLICY_MISMATCH` | 任务与本机验证策略/能力不一致 | 标记失败，不自动重试。 |
| `TASK_LEASE_EXPIRED` | 任务租约过期或不再有效 | 立即停止源站新操作并标记失败，不自动重试。 |
| `SOURCE_ACCESS_DENIED` | 源站权限不足或拒绝访问 | 标记 `blocked` 或失败，不自动重试。 |
| `COLLECTOR_AUTH_CHALLENGE` | 验证码、二次验证或需人工验证 | 标记 `blocked`，明确提示人工处理。 |
| `ADAPTER_NOT_FOUND` | 未注册或不支持的适配器/操作 | 标记失败，不自动重试。 |
| `LOCAL_STORAGE_FULL` | SQLite、日志或结果队列不可写 | 停止领取新任务，标记健康异常。 |
| `PROCESS_INTERRUPTED` | 非正常退出后恢复发现未完成任务 | 仅在可幂等且租约有效时进行一次受限重试。 |
| `INTERNAL_ERROR` | 未分类本地错误 | 记录脱敏错误摘要，最多重试 3 次。 |

可重试任务采用带随机抖动的指数退避，默认序列为 30 秒、2 分钟、10 分钟、30 分钟、2 小时，受 `retry.maxAttempts`、策略 `maxAttempts`、任务租约和策略频率限制共同约束，取其中更严格者。重试次数达到上限后必须转 `failed`，并保留最后错误码；任何异常都不得形成紧密循环或无上限重试。

## 7. 站点适配器扩展约定

适配器按稳定 `adapterKey` 注册，宿主禁止使用甲方名称条件分支驱动执行逻辑。后续新增适配器必须实现等价于下列契约的接口，并在启动时由注册表显式注册：

```text
Adapter
  Manifest() -> adapterKey, adapterVersion, supportedOperations, capabilities
  Preflight(task, policy, environment) -> pass | blocked(errorCode)
  Execute(ctx, task, checkpoint) -> records, checkpoint, stats, terminalStatus, error
  Normalize(sourceRecord) -> allowlist-checked result payload
  Redact(errorOrLogContext) -> safe diagnostic payload
```

- `Manifest` 的 `adapterKey` 全局唯一；启动时发现重复键、空版本、空能力或未知操作必须失败。
- `Preflight` 只检查本机条件、用户授权和策略，不得读取超出任务范围的数据。
- `Execute` 必须可取消、遵守任务/租约截止时间，并仅通过注入的执行器访问目标系统；不得直接读取环境变量中的账号秘密。
- `Normalize` 必须强制字段白名单、字段大小限制和去重键，未允许字段直接丢弃并产生 `DATA_VALIDATION_FAILED` 摘要。
- `Redact` 是日志和错误上报的唯一适配器自定义出口，必须移除令牌、Cookie、账号、页面正文和可能的个人信息。

本任务必须提供 `simulation` 适配器（建议键名 `simulation`），并提供至少四种可配置场景：成功、部分成功、前 N 次网络失败后成功、不可重试失败。该适配器的结果仅含固定模拟标识和计数，不得伪造甲方内容；它是本任务端到端验收的唯一采集实现。

## 8. 日志、查询和健康可观测性

日志以 JSON Lines 记录，字段至少包括 `timestamp`、`level`、`component`、`eventType`、`taskId`（如有）、`attemptId`（如有）、`traceId`（如有）、`errorCode`（如有）和 `message`。消息必须由统一脱敏器处理，禁止记录 HTTP `Authorization`、刷新凭证、Cookie、密码、激活码、完整 URL 查询参数、模拟以外的原始记录或异常堆栈中的敏感片段。

`status` 命令至少显示：当前宿主状态、版本、运行模式、实例 PID（仅本机）、已注册适配器、有效策略摘要、队列各状态计数、当前任务、最近 20 条任务事件、最近错误码、下一次重试时间、日志目录和状态库健康情况。查询失败时应返回非零退出码，且不得因状态查询启动网络请求、浏览器或调度器。

客户端必须记录以下生命周期事件：启动、配置校验失败、单实例冲突、策略失效、任务接收、状态转换、重试计划、重试耗尽、适配器拒绝、停止请求、优雅退出、非正常恢复和本地存储异常。日志可用于支持排障，但不替代平台审计。

## 9. 验收标准与验证场景

后续开发完成时，至少应满足并自动化验证下列场景：

1. 使用 `collector.example.yaml` 的复制配置，在 Windows 当前用户目录启动 `collector-host start` 成功；不提供凭证时 `simulation` 模式仍可运行，`platform` 模式在调度前清晰失败。
2. `collector-host run-once` 可执行成功模拟任务，并在 SQLite 中查询到 `queued → validating → running → reporting → succeeded` 的完整事件链、开始/结束时间和模拟结果计数。
3. 部分成功模拟任务以 `partial_succeeded` 结束，状态查询能看到成功数、拒绝数和脱敏原因，不能被显示为全量成功。
4. 模拟网络异常按配置指数退避；达到 `maxAttempts`、租约到期或策略限制后进入 `failed`，日志和状态库包含最后错误码、次数和下一次重试时间（若有），且测试证明不存在无限循环。
5. `stop` 或控制台中断发生时，客户端停止领取新任务，向当前模拟执行传递取消，持久化 `cancelled` 或可恢复检查点，并在宽限期内退出；再次启动不会重复把未知副作用任务直接标为成功。
6. 第二个实例启动被拒绝，原实例不受影响；`status` 可离线读取原实例的队列、错误和日志路径。
7. 测试覆盖配置校验、状态转换、重试上限、重启恢复、受控停止、凭证不落明文、日志脱敏和模拟适配器注册；测试运行不访问真实网站或真实平台。
8. 新增一个测试适配器仅通过实现并注册约定接口即可被调度器发现；重复键、能力不匹配和未知操作均在执行器启动前失败。

## 10. 后续开发拆分与依赖

建议后续按以下顺序实施，避免先接真实站点或平台接口：

1. 创建 `client/collector` 模块、配置、数据目录、单实例和安全存储端口；实现 `start` / `status` / `stop` 基础生命周期。
2. 实现 SQLite 仓储、状态机、事件审计、轮转脱敏日志和状态查询；先以单元测试固化状态转换规则。
3. 实现调度器、取消上下文、有限退避、重启恢复以及 `simulation` 任务源和模拟适配器，完成本地端到端验收。
4. 在平台侧采集接口和已签名策略实际交付后，实现 `TaskSource`、`ResultReporter`、令牌刷新和租约心跳的 HTTPS 适配器，并与前置文档的 `/api/collector/v1` 契约联调。
5. 经甲方授权、数据字段白名单和安全评审完成后，为单独 `adapterKey` 新增具体站点适配器；该工作须另立任务，不包含在本任务验收内。

## 11. 已知依赖与风险

- 任务 `deployment-e89f2b122a` 已完成方案梳理，但其目标平台采集接口、设备注册、策略签名和任务模型尚未在当前 `server/` 中实现。因此本任务的可执行验收基线必须以 `simulation` 模式为准，`platform` 模式只定义端口和失败行为。

- 当前仓库 `server/web-api/configs/application.properties` 含开发连接配置，客户端实现不得读取、复制、打包或引用该文件；客户端配置必须独立、示例化且不包含真实秘密。
