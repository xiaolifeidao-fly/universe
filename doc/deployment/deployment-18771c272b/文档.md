# 搭建 `server/web-api` Docker 镜像与构建脚本：需求梳理

## 1. 任务目标

为当前仓库的 `server/web-api` 聚合服务建立可复现、可部署的 Docker 镜像构建能力。后续实施需适配 `server/` 下的 Go workspace / 多模块结构，明确镜像构建上下文、依赖缓存、运行时配置注入、监听端口、健康检查、数据库初始化边界和最终镜像内容。

本阶段只完成需求梳理并固化后续实施依据，不新增 Dockerfile、不调整接口或业务逻辑，也不执行任务状态流转。

## 2. 当前工程核查结论（2026-08-14）

### 2.1 Go workspace 与编译边界

| 项目 | 当前事实 | 对 Docker 实现的要求 |
| --- | --- | --- |
| Go 版本 | `server/go.work` 与各模块声明 Go 1.21 | 构建阶段应使用 Go 1.21 系列镜像，避免以本机 Go 1.24 的成功结果代替目标工具链验证。 |
| workspace 模块 | `common`、`contract`、`delivery-api`、`service`、`web-api` | Docker 构建上下文必须覆盖这些相邻模块。 |
| `web-api` 模块依赖 | `server/web-api/go.mod` 通过 `replace ... => ../...` 引用四个相邻模块 | 不能以 `server/web-api` 作为唯一构建上下文；否则 Docker 无法复制 `../common` 等目录。 |
| 现有编译方式 | `server/web-api/build.sh` 在模块目录执行 `GOWORK=off go build -o bin/web-api .` | 容器构建可沿用 `GOWORK=off` 和相对 `replace`，但必须在镜像内保留 `server/` 下的相对目录结构。 |
| 本机编译验证 | 现有 `build.sh` 可成功生成约 19 MB 的 macOS arm64 二进制 | 证明当前模块闭环可编译；该产物不可复制进 Linux 镜像，Docker 必须在 Linux 构建阶段重新编译。 |

因此，约定构建入口为在 `server/` 目录执行：

```bash
docker build -f web-api/Dockerfile -t universe-web-api:local .
```

Dockerfile 放在 `server/web-api/Dockerfile`，与构建上下文配套的忽略文件放在 `server/.dockerignore`。

### 2.2 服务启动与运行目录

- `server/web-api/main.go` 启动时先调用 `httpx.Boot("web-api")` 建立数据库连接，再创建 Gin 路由并监听端口；数据库连接失败时服务不会进入可用状态。
- `httpx.Boot` 当前固定从**进程工作目录**读取 `configs/application.properties`。文件缺失、读取失败或 `sqlconn` 为空都会导致启动失败。
- HTTP 地址优先级为 `WEB_API_ADDR` > `server.address` > `:10001`。容器内默认应明确设为 `:10001`，确保监听全部容器网卡。
- `GET /healthz` 已存在并返回 HTTP 200，可作为容器健康检查端点。但由于路由只会在数据库初始化成功后建立，健康检查同时反映启动阶段数据库连接是否成功。
- 当前 `start.sh` 使用 `nohup`、PID 文件、日志文件和宿主端口探测，适用于本地后台运行，不适合作为容器入口。容器必须以前台二进制作为 PID 1，日志写 stdout/stderr。
- 当前服务运行路径没有读取静态前端资源、模板文件或内嵌资源；运行镜像不需要复制 `client/` 或其他静态目录。
- 服务启动不执行 `AutoMigrate`，SQL 与 `server/migrations/` 不是 web-api 正常启动所需文件。数据库建表和迁移必须由部署前置步骤或独立迁移任务完成，不应因镜像构建而自动执行。

### 2.3 配置与敏感信息

- 当前 `server/web-api/configs/application.properties` 含数据库、Redis、鉴权和外部服务配置，其中包括实际或疑似实际的内网地址、账号、密码或开发密钥。该文件不得复制进最终镜像，也不得作为 Docker 构建参数传入。
- 当前真正被 web-api 启动路径读取的配置至少包括：
  - `sqlconn`
  - `server.address`（仅在 `WEB_API_ADDR` 未设置时）
  - `auth.token_ttl_seconds`
  - `auth.token_secret`
- `auth.token_secret` 参与用户令牌签发与校验，生产容器不得沿用仓库中的开发默认值。运行时配置契约必须将其视为必填秘密，与数据库 DSN 一样由部署平台注入。
- `auth.default_username`、`auth.default_display_name`、`auth.default_password` 仅由独立的 `identityinit` 初始化命令读取，不是 web-api 进程启动依赖；本镜像不应在启动时自动创建默认管理员。
- Redis、聊天模拟、WhatsApp AI、Ark、LLM 等配置当前不在 web-api 启动路径直接读取。本任务可以为兼容配置模板保留空键，但不得虚构其必填性或改变业务接入行为。
- DSN 包含 `loc=Local`，容器时区会影响时间解释。运行镜像应明确时区策略：默认使用 UTC，或通过 `TZ` 运行时变量和 `tzdata` 支持部署环境指定时区；不得无说明地依赖基础镜像默认时区。

## 3. 后续实施交付物

### 3.1 `server/web-api/Dockerfile`

必须采用多阶段构建，至少包含构建阶段和运行阶段：

1. **依赖缓存层**
   - 构建上下文为 `server/`。
   - 先复制 `web-api`、`common`、`contract`、`service`、`delivery-api` 的 `go.mod` / `go.sum`，保持目录关系。
   - 使用 BuildKit cache mount（若项目目标环境支持）缓存 `/go/pkg/mod` 和 Go build cache；不把缓存复制到最终镜像。
   - 执行依赖下载或校验时不得依赖宿主机模块缓存。

2. **编译层**
   - 再复制上述五个模块的源码；不复制 `server/web-api/bin`、`logs`、`run` 和真实配置。
   - 在 `web-api` 模块目录执行等价于 `CGO_ENABLED=0 GOWORK=off go build -trimpath -ldflags="-s -w" -o /out/web-api .` 的 Linux 编译。
   - 不直接复用宿主机已有 `server/web-api/bin/web-api`。
   - 构建应兼容常见的 `linux/amd64` 与 `linux/arm64` Docker 平台；不在 Dockerfile 中硬编码宿主架构。

3. **运行层**
   - 使用精简且可维护的运行基础镜像；必须包含应用 TLS 请求所需的 CA 证书。若支持 `TZ`，同时包含或正确挂载时区数据。
   - 创建非 root 用户运行服务。
   - 工作目录固定，例如 `/app`，并保证启动前存在 `/app/configs/application.properties`。
   - 只复制 Linux 二进制、容器 entrypoint 和必要的无敏感配置模板；不包含 Go 工具链、源码、模块缓存、本地二进制、日志、PID 文件、SQL 或迁移文件。
   - 默认设置 `WEB_API_ADDR=:10001`，声明 `EXPOSE 10001`。
   - 入口使用 `exec` 启动 `/app/web-api`，使信号可直接传给主进程；不得使用 `nohup`、后台符号 `&` 或 PID 文件。
   - `HEALTHCHECK` 请求 `http://127.0.0.1:10001/healthz`。若允许运行时改变容器内端口，应由 Compose/Kubernetes 同步覆盖健康检查；推荐部署时只改变宿主映射，不改变容器内 `10001`。

### 3.2 `server/.dockerignore`

必须与 `server/` 构建上下文匹配，并确保：

- 排除 `.git`、IDE 文件、系统文件、覆盖率/测试产物、临时文件。
- 排除所有模块的 `bin/`、`logs/`、`run/`、本地可执行文件和构建缓存。
- 排除 `web-api/configs/application.properties`、`application_dev.properties`、`.env*`、证书、私钥及其他可能含秘密的文件。
- 排除本镜像不需要的 SQL、`migrations/` 和文档；如采用白名单规则，应显式保留五个必要模块的 `go.mod`、`go.sum` 与源码。
- 不得误排除编译所需的内部包、`go.sum` 或相邻模块，否则依赖缓存层和源码编译层会出现不一致。

### 3.3 容器启动/配置脚本

应新增独立的容器入口脚本（建议 `server/web-api/docker-entrypoint.sh`）和无敏感模板（文件名可按实现确定），职责仅限运行配置准备与前台启动：

1. 使用 `set -eu` 或等效严格模式。
2. 校验至少以下必填变量：
   - `WEB_API_SQLCONN`
   - `WEB_API_AUTH_TOKEN_SECRET`
3. 将环境变量安全地映射为当前代码所需的 properties 键，并生成 `/app/configs/application.properties`。
4. 对 properties 特殊字符采用不会被 shell 展开或截断的写入方式；不得 `eval`，不得把秘密打印到日志。
5. 为 `auth.token_ttl_seconds` 提供明确且无敏感的默认值（可沿用当前 `604800`），并校验其为有效正整数，避免当前 `strconv.Atoi` 失败后静默得到 0。
6. 默认监听 `:10001`；`WEB_API_ADDR` 可覆盖，但部署文档需提示健康检查和端口映射同步问题。
7. 最终执行 `exec /app/web-api`；可将额外参数原样传给进程，但不得转为宿主后台管理逻辑。

若实施选择直接增强 `common/middleware/httpx` 支持环境变量覆盖，也必须保持以下边界：未设置容器变量时，本地仍读取现有 properties；覆盖逻辑集中在基础设施层；不改领域服务和 HTTP 业务；真实秘密仍不得进入镜像层。相比修改通用代码，本任务优先采用独立 entrypoint 生成运行配置，以缩小变更范围。

### 3.4 构建脚本

现有 `server/web-api/build.sh` 是本地 Go 二进制构建脚本，应保留其当前用途。后续应新增或扩展一个语义明确的镜像构建入口（建议 `server/web-api/build-image.sh`），要求：

- 无论从仓库哪个工作目录调用，都能定位 `server/` 构建上下文。
- 默认镜像名可配置，例如 `${IMAGE_NAME:-universe-web-api}`，标签可由参数或 `${IMAGE_TAG:-local}` 指定。
- 使用 `docker build -f web-api/Dockerfile ... <server-context>`，不得错误地把 `web-api/` 作为上下文。
- 采用严格模式并在 Docker 不可用时返回非零和明确错误。
- 不接受或转发数据库 DSN、Token secret 等运行时秘密作为 `--build-arg`。
- 可将额外的非敏感 Docker build 参数透传，但行为需在脚本帮助或注释中明确。

## 4. 运行时配置契约

| 用途 | 环境变量 | 生成的配置键 | 要求 |
| --- | --- | --- | --- |
| HTTP 监听地址 | `WEB_API_ADDR` | `server.address`（可选同步） | 默认 `:10001`；环境变量本身已由 `main.go` 优先读取。 |
| MySQL DSN | `WEB_API_SQLCONN` | `sqlconn` | 必填秘密；缺失时 entrypoint 非零退出。 |
| Token 签名密钥 | `WEB_API_AUTH_TOKEN_SECRET` | `auth.token_secret` | 必填秘密；不得使用仓库配置中的开发默认值。 |
| Token 有效期 | `WEB_API_AUTH_TOKEN_TTL_SECONDS` | `auth.token_ttl_seconds` | 可选，默认 `604800`，必须为正整数。 |
| 日志目录 | 无需强制变量 | `log.dir` | 容器日志由 stdout/stderr 收集；模板可设为 `/tmp` 或保留空值，不应要求持久化 `logs/`。 |
| 时区 | `TZ` | 不写 properties | 可选；默认策略必须在镜像或部署说明中明确。 |

其他当前配置键如 Redis、聊天模拟、WhatsApp AI、Ark、LLM 等，只有在确认运行路径已读取时才纳入环境变量契约。若为兼容现有配置解析而写入模板，使用空值或安全默认值，不得拷贝本地配置内容。

## 5. 数据库、资源与部署边界

1. **MySQL 是启动硬依赖**：容器验证必须使用已完成建表/迁移、且网络可达的测试数据库。`/healthz` 不能在无数据库情况下用于证明镜像可运行。
2. **迁移不随 web-api 自动执行**：`server/bizline.sql`、`server/delivery.sql`、`server/identity.sql` 与 `server/migrations/` 由独立部署步骤管理，不复制进运行镜像，不在 entrypoint 中自动执行。
3. **管理员初始化独立执行**：`identityinit` 是独立命令，不在 web-api 容器启动时自动运行，避免每次重启产生数据或权限副作用。
4. **无静态资源依赖**：当前 web-api 不托管前端资源，无需复制 `client/web`、上传目录或原型 JSON。
5. **日志不落镜像工作区**：应用与 Gin 日志由容器运行时收集；除非后续明确要求文件日志，不创建或挂载 `server/web-api/logs`。
6. **Secret 只在运行时注入**：优先使用部署平台 Secret 或只读挂载；若通过环境变量注入，不在镜像历史、构建日志、示例文件和版本库中出现真实值。

## 6. 非目标

- 不新增 Docker Compose、Kubernetes、Helm、CI/CD 或镜像仓库发布逻辑。
- 不修改 HTTP 路由、业务 service、Repository、表结构或鉴权规则。
- 不把数据库迁移、默认管理员创建或数据导入绑到 web-api 启动。
- 不更改本地 `build.sh`、`start.sh`、`stop.sh`、`redev.sh` 的既有职责，除非仅为与新增镜像脚本消除明确命名冲突。
- 不将 Redis、LLM 或第三方服务配置扩大为本任务的强制运行依赖。
- 不清理仓库中现有敏感配置文件本身；若需凭证轮换或配置治理，应另立安全任务。本任务只保证其不进入镜像。

## 7. 验收标准

1. 在 `server/` 上下文执行 `docker build -f web-api/Dockerfile -t universe-web-api:local .` 成功，或执行新增镜像构建脚本得到等价结果。
2. 构建过程使用镜像内 Go 1.21 工具链编译 Linux 二进制，不依赖宿主 `bin/web-api`、宿主 Go module cache 或 `go.work` 外目录。
3. 使用可达且已初始化的测试 MySQL、有效 Token secret 启动容器后，web-api 作为前台 PID 1 运行，并在容器内 `:10001` 提供服务。
4. `GET /healthz` 返回 HTTP 200，容器健康状态变为 healthy；停止容器时进程能接收终止信号并退出。
5. 未设置 `WEB_API_SQLCONN` 或 `WEB_API_AUTH_TOKEN_SECRET` 时，容器在启动 web-api 前明确报错并以非零状态退出，日志不回显变量值。
6. 最终镜像以非 root 用户运行，包含 CA 证书和明确的时区策略，不包含源码、Go 工具链、模块/编译缓存、本地 `bin/`、`logs/`、`run/`、SQL、迁移文件或真实 properties 配置。
7. `docker history --no-trunc`、镜像文件系统检查和构建日志中不出现数据库 DSN、Token secret、当前仓库配置中的密码或私有连接值。
8. 不设置容器相关变量时，现有本地 `server/web-api/build.sh` 仍可成功编译，本地配置读取和 `WEB_API_ADDR` 优先级不回归。
9. 第二次无源码变更构建能够复用依赖层；仅修改 web-api 源码时，不应重新下载所有 Go 依赖。
10. 镜像可分别面向 `linux/amd64` 和 `linux/arm64` 构建；至少验证当前部署目标平台，且 Dockerfile 不硬编码单一架构。

## 10. 实施决策结论

后续实现应采用“`server/` 构建上下文 + `server/web-api/Dockerfile` 多阶段构建 + `server/.dockerignore` 严格排除 + 独立前台 entrypoint + 运行时生成无持久化 properties”的方案。该方案能保持当前相对 `replace` 依赖可解析，避免把仓库中的真实配置带入镜像，并明确区分 web-api 运行、数据库迁移和管理员初始化三个职责。
