# 移动端 PWA 与远程命令架构

## 需求背景与目标

当前项目已经完成 PC 网页版交付任务面板，但任务执行依赖浏览器直接访问运行在本机的 Python bridge，无法在手机端稳定完成远程管理和执行。

本需求建设一套与 PC 前端代码完全独立的移动端 PWA：客户端位于 `client/app`，服务端 HTTP API 位于 `server/app-api`。移动端通过服务端提交持久化命令，由当前登录用户对应的 Python 插件主动领取并在项目工作目录执行；执行进度、结果、Git 操作和云端文档再同步回服务端，形成可在移动端完成的交付管理闭环。

交付目标包括：

- 提供可添加到主屏幕的成熟移动端 PWA，不开发原生 App。
- 支持项目、需求、任务和依赖的查看、新建及修改，并可发起任务拆解。
- 支持任务会话、单任务/批量/顺序执行、停止、实时进度和结果恢复。
- 完整远程化现有 Git 状态、分支、差异、初始化、子模块、准备、推送和合并能力。
- 项目开启云存储时，从服务端 OSS 查看需求、设计、测试、原型、执行产物和附件。
- 通过 Web Push 通知任务完成、失败、阻塞以及 AI 回复完成。

## 范围与不做的事

### 本期范围

- `server/app-api` 独立 Go API 服务、用户命令中心、插件领取协议、移动业务 API、OSS 读取和 Web Push。
- `plugin/delivery-task-planner/delivery_bridge` 主动轮询 Worker、项目工作目录匹配、执行适配、进度和文档回传。
- `client/app` 独立 Next.js PWA、移动设计系统、交付管理、远程执行、Git、文档和通知界面。
- iOS 16.4+ 添加到主屏幕后 Web Push，以及主流 Android PWA。
- 文本框直接使用 iOS/Android 系统键盘听写；支持既有图片和文件上传能力。

### 不做的事

- 不开发 iOS/Android 原生 App，不使用原生打包壳。
- `client/app` 不引用 `client/web` 的组件、样式或 API 文件，也不与 PC 前端共用构建和发布流程。
- 不在移动端提供插件升级、开发环境安装或任意 Shell 命令。
- 本期不开发“按住说话 + ASR”能力，不依赖 iOS 不支持的 Web Speech API 实时流式听写。
- 项目未开启云存储时，不通过服务端临时代理本机文件。

## 关键业务与技术约束

### 命令与插件

- 每个当前登录用户对应一个 Redis 领取队列；命令至少包含用户、业务线、项目、命令类型和输入参数。
- 数据库中的命令记录和事件是权威数据，Redis 只承担待领取通知，不保存权威结果。
- 命令必须有稳定幂等键；相同业务提交不得重复创建或重复启动本地执行。
- 插件使用当前登录用户凭证轮询，只能领取该用户的命令。多台同用户插件竞争时，同一命令只能由一台插件确认领取。
- 插件必须先确认本机存在该项目对应的 workspace 映射才可领取，不能由服务端下发任意本机路径。
- 插件未领取或领取后失联时等待 2 分钟，再依据权威状态进入超时或重新调度判定。
- 取消采用尽力而为语义：保存取消请求，插件轮询后尝试停止，并回传最终状态。
- PWA 不直接访问 Python bridge；所有远程操作均通过 `server/app-api` 创建并查询命令。

### 进度与通知

- PWA 前台通过 SSE 接收活动和进度，按事件游标重连并通过快照恢复，不能重复展示事件。
- PWA 进入后台后不依赖持续运行的 JavaScript；完成、失败、阻塞和 AI 回复完成通过 Web Push 通知。
- Web Push 权限被拒绝或订阅失效不能影响核心任务操作。

### 文档与 OSS

- 复用项目级云同步开关。只有开启对应云存储后，插件才把项目文档同步到服务端 OSS。
- 移动端覆盖需求、设计、测试用例、测试报告、HTML 原型、执行产物和附件。
- 沿用现有单个同步文件 8 MB 上限，以及相同项目、类别和相对路径保存最新快照的策略。
- 移动端通过服务端受控读取或短时签名地址预览 OSS 文件，不能暴露 OSS 密钥或本机绝对路径。
- 未开启云存储时显示明确降级提示，文档仍只能在执行电脑查看。

### 移动体验

- `client/app` 必须拥有独立依赖、路由、请求层、组件、样式、设计 token、构建及发布流程。
- 产品可以保持现有品牌、登录体系、权限规则和服务端字段语义，但不能复制成缩小版 PC 控制台。
- 采用成熟 App 导航和交互：底部主导航、适合触摸的操作目标、清晰层级、加载/空态/错误态、危险操作确认和断线恢复。
- 覆盖刘海安全区、软键盘弹起、长文本、窄屏、横竖屏切换和弱网场景，界面不得遮挡或溢出。

## 勘察到的工程落点

- `client/app/`：当前为空目录，是独立移动 PWA 的唯一客户端落点。
- `server/app-api/`：当前为空目录，所有移动端 HTTP handler 和独立服务装配均放在这里。
- `server/service/delivery/`：已有项目、需求、任务、依赖、执行批次和云同步领域能力；新增权威命令模型及服务逻辑应继续归属该领域。
- `server/service/business/`：已有业务需求会话、消息、附件和远端轮询语义，移动业务 API 应调用该服务而非复制逻辑。
- `server/service/identity/`：已有登录用户和权限能力，用户队列身份必须由服务端认证结果确定。
- `server/common/objectstore/oss.go`：已有 Aliyun OSS 上传能力，需要补充受控读取或签名访问能力。
- `server/delivery-api/` 与 `server/web-api/`：PC 端已有 handler 和聚合装配；移动 API 可以复用领域 Service，但不能把移动 handler 写回 PC API。
- `plugin/delivery-task-planner/http_bridge.py`：已有本地 HTTP 路由和 `ExecutionBridge` 入口。
- `plugin/delivery-task-planner/delivery_bridge/`：已有任务执行、会话、Git、文档、队列和进度同步实现，是远程 Worker 的适配落点。
- `client/web/`：现有 PC 控制台，仅作为业务行为和接口语义参考；不作为移动端代码依赖。
- `server/migrations/20260823_delivery_program_cloud_sync.sql` 与 `server/service/delivery/program.go`：已有项目云存储开关、同步类别和 OSS 上传约束。

## 总体验收标准

1. 用户能够在独立 PWA 中登录，查看项目、需求和任务，并完成需求新建与编辑、任务拆解确认、任务修改和依赖调整。
2. PWA 发起的会话、执行、停止和 Git 操作全部生成服务端持久化命令，由对应用户的 Python Worker 领取；PWA 不直接连接本机 bridge。
3. 相同幂等请求不会产生重复任务执行；多插件竞争不会重复领取；插件掉线、超时、恢复及尽力取消均有可审计状态。
4. 前台 SSE 能实时展示活动，刷新、断网重连和切后台后可从快照恢复且不重复事件。
5. Git 状态、分支、差异、初始化、子模块、准备、推送和合并能力可以从移动端发起并获得明确结果。
6. 项目开启云存储后可以在移动端受控查看全部约定文档和附件；关闭时不泄露或代理本机文件，并展示清晰提示。
7. PWA 可在 iOS 16.4+ 和主流 Android 添加到主屏幕；Web Push 支持授权、撤销、失效清理和业务目标跳转。
8. 常见移动视口、安全区、软键盘、长文本和弱网场景无阻断性问题，交互达到成熟生产级 App 水平。
9. 核心服务具备自动化测试，移动端关键流程具备端到端测试和真实设备/视口截图验证。
10. 现有 `client/web`、`server/web-api` 及浏览器直连本地 bridge 的 PC 流程通过回归，不因移动架构改造而失效。

## 测试准备条件

- 至少两个不同用户账号，用于验证 Redis 用户队列和权限隔离。
- 同一用户至少两台可运行插件的测试电脑，用于验证竞争领取和 workspace 匹配。
- 一个开启 OSS 云同步的项目和一个关闭云同步的项目。
- 可用的 Redis、MySQL、Aliyun OSS、HTTPS 域名及 Web Push VAPID 配置。
- iOS 16.4+ Safari 添加到主屏幕环境和一台主流 Android 浏览器设备。
- 包含未领取、执行中掉线、重复提交、取消竞态、SSE 断线和失效 Push 订阅的测试数据。

## 待确认问题

无阻塞性待确认问题。任务实施阶段如发现同一用户多插件的 workspace 映射需要新增 PC 配置入口，应保持“仅已配置项目工作目录的插件可以领取”这一安全约束，不得回退为服务端下发本机绝对路径。
